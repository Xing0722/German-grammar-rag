# 设计决策记录

每一条:**决策 → 选项 → 当前选择 → 依据 → 状态**。面试被问"为什么这样做",就看这里。
状态含义:**已验证** = 我在真实 PDF 上跑过;**借用** = 来自 issue-rag,没有自己验证;**待实验** = 需要用评测集回答。

## D1 用什么工具提取 PDF 文字
- 选项:pdftotext(poppler)、PyMuPDF、pdfplumber。
- 选择:**pdftotext -layout**。
- 依据(已验证):PDF 里每个小节开头有隐藏标记 `@@1.2@@`,全文 52 个,和目录一一对应。
  pdftotext 把标记放在小节开头;PyMuPDF 的阅读顺序会把标记放到小节中间(我在 1.2 小节上看到,没有逐个检查),按它切会切错;
  pdfplumber 读不到标记(变成私有区字符),输出里还有 64 个"康熙部首"字符(⼈ 而不是 人),搜"人"会匹配不上。
- 面试会问:为什么不直接用最流行的库?→ 因为提取结果取决于工具,我逐个对照过。

## D2 评测单位是什么
- 选择:**小节**(标准答案 = 小节号,如 6.3)。
- 依据:教材自带编号结构;标准答案不需要 LLM 当裁判,便宜且可复核。
- 代价:一个问题可能由两个小节共同回答,所以 gold 是列表,命中任意一个算对。

## D3 检索单位和块大小
- 问题:33/52 个小节超过 1,200 字符,最长的 6.3 有 9,324 字符;embedding 模型会截断过长输入。
- 选择:小节再切成**子块**,默认 500 字符、重叠 80 字符,每个子块记着自己属于哪个小节。
- 依据(已验证):500 字符得到 211 个子块,52 个小节全部覆盖;1000 字符得到 114 个。
- 状态:**待实验**(E4:块大小是否影响命中率)。

## D4 怎么切
- 选择:按**行**切,不切断一行;一行超长才硬切;下一块以上一块的最后几行开头(重叠);
  每块开头加标题 `[6.3] 可分前缀`。
- 依据:表格每一行是一行文字,不切断才不会把变格表拆坏;标题前缀让单独一块也知道自己属于哪里(借鉴 issue-rag)。

## D5 分词
- 选择:中文用 jieba;拉丁文字(含 ä ö ü ß)整词保留并转小写。
- 依据(已验证):issue-rag 的正则 `[A-Za-z0-9_.\-/]+` 会把 `Abhängigkeiten` 切成 `Abh` + `ngigkeiten`,并丢掉全部汉字。

## D6 停用词
- 选择:**默认不删**。
- 假设:德语语法书里 der/die/das/dem/den/des 和 mit/nach/bei/seit/von/zu/aus 就是用户要查的内容,
  常见德语停用词表会把它们全删掉。
- 状态:**待实验**(E2)。这只是假设,结果可能是"影响很小",那也要如实写。

## D7 向量模型
- 选择:BAAI/bge-m3(多语言)。
- 依据:问题是中文、文档是中文夹德语,英文模型(issue-rag 用的 bge-base-en)处理不了中文。
- 状态:**未验证**。据我所知它支持中德和长文本,但还没有在本项目里跑过;换模型只改 `--model`。

## D8 混合检索
- 选择:BM25 + 向量,用 RRF(k=60)合并。
- 依据:RRF 只看名次,BM25 分数和余弦相似度不在同一个尺度,不能直接相加。k=60 **借用**自 issue-rag,没有调过。
- 状态:E1 检验混合是否真的比单独的好。

## D9 子块得分怎么变成小节得分
- 选择:一个小节的名次 = 它**最好的子块**的名次。
- 依据:简单、可解释;缺点是一个小节只要有一个子块碰巧匹配就会靠前。

## D10 引用检查
- 选择:要求 LLM 用 `[小节号]` 标注;程序检查被引用的小节是否真的被检索到。
- 局限:只能发现"编造了不存在的引用",**不能**证明被引用的内容支持结论。
