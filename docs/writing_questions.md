# 怎么写评测问题

评测集是这个项目最重要的部分,也只有你能写:你是学习者,也是唯一能判断答案对不对的人。
目标 **40–60 题**(少于 30 题,置信区间会宽到没法下结论)。

## 格式 (`data/eval/questions.jsonl`,每行一个)

```json
{"id": "q01", "query": "dem 什么时候用?", "gold": ["1.2"], "style": "natural"}
```

- `gold` 是**列表**:如果两个小节都能回答这个问题,两个都写,命中任意一个算对。
- `style` 是 `natural`(自然提问)或 `title`(故意用小节标题里的词,见下)。

## 规则

1. **先写问题,后标答案。** 不要先翻文档再照着写,那样问题会带着文档的措辞,关键词检索占便宜。
   写完之后再对照目录填 `gold`。
2. **用你真实会问的话,中文。** 例:"dem 什么时候用?"、"可分动词在句子里放哪?"、"weil 后面动词放哪里?"。
3. **要有难题。** 至少三分之一的问题要在容易混淆的小节之间做选择:
   第一虚拟式和第二虚拟式、可分前缀和不可分前缀、接二格的介词和接三格的介词、
   现在完成时和过去完成时。52 个小节太少,太简单的问题会让所有方法都接近满分,什么也比较不出来。
4. **留一部分"标题式"问题。** 大约 10 题,直接用小节标题里的词来问(例如"冠词的选择与省略")。
   实验 E3 用它们和自然提问对比,检验关键词检索是不是占了标题的便宜。
5. **不要把教材原文粘贴进问题。** 问题文件会提交到公开仓库。
6. **覆盖面。** 52 个小节里,尽量每章都有题,别把题都堆在名词和冠词。

## 写完之后

- 过几天自己再看一遍,删掉措辞和教材一模一样的题,或者标成 `title`。
- 用 `python src/evaluate.py --mode bm25 ...` 跑一遍,看哪些题没找到(`gold not in the retrieved list`),
  逐题分析原因:是问题太含糊,标准答案标错了,还是检索真的失败了?这就是 README 里"失败案例分析"的素材。
